# Handoff — M5 inventory implemented locally

Continued the M4 working tree after the user's “yes.” User explicitly chose:
**allow orders when stock runs out and show a low-stock warning**. Work began
September 28 and finished after midnight September 29, Asia/Calcutta.

## Delivered

- Admin Inventory screen: create, rename, set thresholds, archive/reactivate;
  receive stock, record wastage, enter physical counts with reasons; searchable
  active/low/all views and paged movement history. Cashiers have read-only access.
- Simple product stock link editor with quantity per sale, shared by all variants.
  It refuses to overwrite multi-link recipes. The domain consumption/reversal
  engine supports all links in the existing schema for the later recipe editor.
- Quantities calculated as integer thousandths and stored as canonical decimals
  in the existing REAL columns (three decimal places; units remain immutable).
- Migration 006 adds stock versions, creation/movement request references,
  product-link versions, movement order-item/reversal references, balance-after,
  uniqueness indexes and append-only history triggers. Existing balances/history
  are preserved. Earlier migrations, including uncommitted M4 migration 005,
  were not rewritten.
- KOT transaction deducts stationed items before marking sent. Bill transaction
  deducts remaining stationless pending items before marking sent. No deductions
  on punch, settlement, reprint or request replay.
- Sent cancellation reverses saved sale movements in the same transaction as
  item cancellation. Remapping or archiving the original stock never changes
  the reversal amount. Unique reversal reference prevents duplicate reversals.
- Manual stock mutations use request references for retries. Version checking
  prevents stale counts/metadata edits; a successful retry is recognized before
  version checking. Linked stock cannot be archived until links are removed.
- Negative balances are allowed. Low means qty <= threshold, defaulting to zero.
  `stock.changed`/`stock.low` events carry IDs only, published after commit. Full
  inventory stays behind `stock.read`; order clients refetch relevant warnings.
  OrderScreen shows warnings, including to waiters, and never blocks ordering.
