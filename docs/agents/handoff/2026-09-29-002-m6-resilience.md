# M6 handoff — resilience and Windows packaging

## Outcome

Implemented locally on `main`, preserving all uncommitted M4/M5 work. Nothing was
committed or pushed. Product version is now 0.6.0. Next product milestone: M7,
the multi-ingredient recipe editor using existing product stock links.

## Delivered

- Daily, manual and pre-update `VACUUM INTO` backups with SQLite integrity and
  foreign-key checks, flushed staging files, retention and optional second copy.
  Settings exposes status, configuration and authenticated downloads. A missing
  second drive is reported and does not invalidate the local snapshot.
- Startup must save a verified backup before existing schemas migrate or the
  installed app version changes. Newer schemas are refused. Windows named-pipe
  locking prevents two servers/restores from using the same directory.
- Journaled restore stages and validates first, archives the previous DB and
  WAL/sidecars, resumes interruption, clears sessions and changes the recovery
  generation. Browser queues/drafts from an earlier generation are archived,
  never replayed into restored data.
- Durable browser queue for punch, kitchen send, bill issue and settlement,
  scoped to the originating staff member. Frozen request bodies retain their
  idempotency references; conflicts remain visible for review. New draft rows
  survive acknowledgement of an earlier punch. Draft initialization no longer
  overwrites the saved cart with an empty array on mount.
- Migration 007 adds `kot_requests`: retries return the original KOT IDs and
  cannot accidentally send items from a later round. Existing migrations were
  preserved. Legacy bodyless send remains supported for compatibility.
- Electron utility-process server, health identity checks, backoff, launch
  failure diagnostics, single desktop instance, graceful quit, tray and login
  autostart. Packaged server uses a real data-directory `cwd`; an ASAR archive
  cannot be the working directory on Windows.
- Self-contained x64 NSIS installer with private-network/local-subnet firewall
  rule on TCP 4100. Runtime dependencies are copied from the lockfile install;
  Electron supplies Node and SQLite 13 supplies its Node-API prebuild.
- LAN URLs, local QR rendering and authenticated PowerShell download that creates
  an Edge app-mode desktop shortcut on another counter PC.

## Continuation notes

Read [operations documentation](../../operations/backup-and-recovery.md) for
build, installation, recovery and data paths. Build scripts require closing
anything using `build/desktop/app` first: Windows holds loaded native binaries
open. `npm ci --ignore-scripts` avoids an unnecessary local SQLite compile;
`node node_modules/electron/install.js` downloads the Electron runtime.

Gate scripts: `tools/e2e/m6-resilience.js`, `tools/e2e/m6-desktop.mjs`; instructions
in `tools/e2e/README.md`. The browser gate uses DOM events due to Windows native
click issues and waits for buttons to finish previous asynchronous actions.
For Electron automation, pass `--cdp 4122` on every agent-browser invocation.
The main-process inspector on 9233 is used only for QA; ordinary app launches
enable neither debugging port.

Scratch databases: `.e2e-scratch/m6-browser` and `.e2e-scratch/m6-desktop`.
Test login is Test Admin / 1234. M6 test processes were shut down after validation.
The earlier M5 server on port 4110 was not changed during this milestone.

## Remaining rollout checks and limitations

- Run installer/UAC, firewall access from another PC, Windows-login startup and
  upgrade/uninstall retention tests on a clean Windows machine. The payload was
  exercised here; the installer was not installed on the user's machine.
- Obtain a signing certificate before public distribution.
- Print jobs remain in memory across this milestone. The database keeps KOTs and
  bills, but pending/failed print jobs do not survive restart. Physical printer
  delivery and USB/Bluetooth behavior still require hardware tests.
- Bill void/refund workflow is still absent. M7 recipe configuration remains.
- Browser queues resume only when that browser is open and the originating user
  is signed in; other administrative mutations need a live connection.
