# M7: recipe editing

Implemented on top of the existing multi-link stock engine and local commercial
licensing foundation. Earlier uncommitted work is preserved. No schema migration
was needed for recipes. No commits, deployments, or new installers were produced.

## Behavior

- Inventory > Product stock link > Edit recipe for Pro administrators (also
  available in development mode). Ingredients use their stored stock units and
  quantities per sale; the recipe applies to every variant of that product.
- Up to 100 unique, active ingredients, each 0.001–1,000,000 with at most three
  decimal places. Save atomically replaces the entire recipe. Empty saves ask
  for confirmation in the UI and disable future ingredient deductions.
- GET stock-links remains readable with stock.read. New PUT product recipe
  requires stock.manage and the recipes entitlement. Basic keeps simple links,
  cannot overwrite a multi-ingredient recipe through that endpoint, and retains
  saved recipes and deductions after downgrade.
- Product stock_version is shared with the simple editor. Changed stale writes
  return 409; drafts stay visible for review/reload. Identical/reordered retries
  do not regenerate link IDs, increment the version or broadcast again.
- Recipe edits never alter prior ledger entries. Pending items use the recipe
  at kitchen send or stationless bill issue. Cancellation reverses recorded
  deductions even after changing or clearing the recipe.
- Unsaved product changes, page navigation, reload and explicit logout require
  confirmation; browser unload warns too. Product switching/navigation are
  blocked while a recipe save is pending. Nothing queues edits while disconnected
  from the local hub; an internet connection is not required by the editor.

- 13 new API integration tests use real SQLite and signed Pro/Basic licenses.
  Includes schema/quantity validation, missing/archived ingredients, stale writes,
  retry stability, deliberate second-insert rollback, persistence/restart,
  variant deductions, cancellation after edit/archive, stationless billing retry,
  cashier denial and downgrade behavior.

  rounded to zero and blocked sales. Regression tests cover both recipe and
  simple-link endpoints. Also added app navigation/logout draft protection.

  behavior, draft retention, conflict recovery, ingredient replacement, original
  ledger reversals and confirmed clearing.
- Seven additional browser checks passed for live Basic downgrade and Pro upgrade:
  disabled editor, locked action, API 403 on clear, and unchanged readable recipe.
- Desktop and 390×844 phone views visually inspected. At 390px, document width
  remained 390px; no horizontal page overflow. Browser errors were empty.
- git diff --check passed.
