│ Phase 2 — MasalaPOS Support Connector (Zoho-style on-demand remote access)                                      │
│                                                                                                                 │
│ Context                                                                                                         │
│                                                                                                                 │
│ Phase 1 (live chat + in-app consent remote access) is built, deployed to portal.billnroll.in, and working. It controls the desktop as the logged-in user and cannot reach UAC prompts or elevated windows.                    │
│                                                                                                                 │
│ The user wants the Zoho Assist model instead, and it replaces the in-app remote-control flow:                   │
│ - Support generates a session from Live chat. The restaurant downloads a small connector named with the chat ID (e.g. MasalaPOS-Support-C-1001-<token>.exe).                                                                  │
│ - The restaurant runs it. It requests admin (one UAC prompt), reads the token from its own filename, joins that exact session, shows a chat sidebar, and shares the screen / accepts control.                                 │
│ - Because it runs elevated, it reaches UAC prompts, admin windows, Device Manager, driver installs — the original Phase 2 goal — without a Loc                                            │
│                                                                                                                 │
│ Decisions made:                                                                    │
│ - Role: connector replaces the in-app remote-control path (chat and consent stay).                              │
│ - Elevation: ask for admin at launch.                                              │
│ - Size: tiny stub (~0.2–2 MB) + cached ~80 MB Electron payload (first run only; later sessions reuse the        │
│   cache).                                                                          │
│ - Signing: none yet — pilot only. See risks.                                                                    │
│                                                                                    │
│ How elevated reach actually works (important)                                                                                                                                                     │
│ Running the connector elevated (high integrity) removes the UIPI block, so SendInput drives elevated windows   and capture includes them. But the UAC secure desktop (Winlogon), which even a     │high-integrity process on the normal desktop cannot capture. Zoho/TeamViewer solve this by temporarily turning off the secure desktop (HKLM\...\Policiop = 0) for the session, so UAC prompts     │appear on the normal desktop and become shareable/controllable, then restoring it on exit. The elevated connector does this behind an explicit  through Windows admin prompts"). This is   │the mechanism that makes "admin at launch" deliver real UAC reach and is why no SYSTEM service is needed.       │
