## Delivery

1. Verify the existing test baseline and typecheck.
2. Add integer-paise GST calculations: proportional discount by GST group,
   deterministic remainder allocation, CGST/SGST rounded independently to paise,
   final payable rounded to the nearest rupee (half up). User requested both
   tax-exclusive and tax-inclusive pricing, configurable in Settings. Default is
   exclusive; store the mode in each receipt snapshot. Inclusive extraction
   preserves the gross amount and assigns an odd tax paise to CGST.
3. Preview then issue immutable bills. Persist restaurant and item snapshots;
   assign the gapless number and change order state in one transaction. Reject
   unsent kitchen items; consume stationless pending items at billing. Cashier
   discounts remain capped at the existing 10% role limit; require a reason.
4. Settle the entire outstanding bill with one or more cash/UPI/card entries.
   Validate exact payment sum, persist request reference and actor, and transition
   the order atomically. A zero bill settles with no payment rows. Replays return
   the original result; conflicting reuse returns 409. Separate print retries
   never issue a second bill or collect twice.
5. Receipt printer selected per checkout (remembered on that device), 58/80mm
   ESC/POS and an HTML/browser-print fallback. Reprints use saved snapshots.
6. Billing history, unpaid bills, and admin day-end report: issued sales/taxes,
   payments received that local calendar day (including older bills), outstanding
   balance for that day's bills, and cancellations. Existing cashier report-read
   permission remains valid.
7. Domain, migration, API and print verification; production UI browser check
   through bill, split payment, receipt and report. Update README and handoff.

## Boundaries

integration. Never rewrite earlier migrations. Physical printer validation still
